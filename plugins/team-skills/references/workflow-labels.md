# Workflow labels and state machine

The v2 workflow is driven by GitHub issue labels. Labels are the source of
truth; a GitHub Projects Status field, if the repo uses one, is only a mirror.
`work` ensures these labels exist (create any that are missing with
`gh label create`) before using them.

## Category (exactly one)

| Label | Meaning |
|---|---|
| `bug` | Something is broken |
| `enhancement` | New feature or improvement |

## State (exactly one)

| Label | Meaning | Who acts next |
|---|---|---|
| `needs-triage` | Captured, not yet grilled | `grill` |
| `needs-info` | Waiting on an answer a human must give | the human |
| `needs-business-input` | A business/product decision only the business can make; lives on its own issue | the business |
| `ready-for-agent` | Fully specified; an agent can finish it with zero questions | `deliver` |
| `ready-for-human` | Specified, but a human must implement it (judgment, external access, manual testing) | a human |
| `wontfix` | Will not be actioned | nobody |

Plus one marker: `agent-working` — a `deliver` run has claimed the issue. It
stops two runs grabbing the same ticket. Remove it when the run ends, however
it ends.

`epic` marks a parent issue whose sub-issues are the task graph.

## Transitions

```
(new) ─► needs-triage ─► [grill] ─► ready-for-agent ─► [deliver] ─► closed by PR merge
                           │  │                            │
                           │  └─► ready-for-human          └─► needs-info  (stuck; see deliver)
                           └─► needs-info ─► (answered) ─► needs-triage
                           └─► wontfix
```

`needs-business-input` issues are children of the work that raised them. They
never block unrelated subtasks (see `grill`, "Business questions").

## Rules

- An issue carries one category and one state. If states conflict, stop and
  ask — do not pick one.
- Every comment or issue posted by the workflow starts with
  `> *Generated by AI via the team workflow.*`
- Never apply `ready-for-agent` without an agent brief comment
  (`agent-brief.md`). The label without the brief is a promise nobody kept.
