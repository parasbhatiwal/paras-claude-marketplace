# Writing an agent brief

Adapted from Matt Pocock's `triage` skill (MIT; see `THIRD_PARTY_NOTICES.md`).

An agent brief is the comment posted on an issue when it becomes
`ready-for-agent`. In v2 it is a **contract between a human who is about to
leave and an agent that will not be able to ask them anything**. The issue body
and discussion are context; the brief is what the agent builds against.

## Principles

- **Durable over precise.** The issue may wait days. Describe interfaces,
  types and behavioral contracts. No file paths, no line numbers.
- **Behavioral, not procedural.** Say what the system does, not which function
  to edit. The agent explores the code fresh.
- **Testable acceptance criteria.** Every criterion independently verifiable —
  the agent's TDD loop starts from these.
- **Explicit scope.** State what is out of scope so the agent does not
  gold-plate or wander.
- **Decisions are written down.** Every answer the human gave during the grill
  that constrains the build appears here. If it is not in the brief, the
  agent has never heard it.
- **Assumptions are labelled.** Anything decided by default because the human
  could not answer is listed under *Assumptions*, with the issue tracking it.

## Template

```markdown
> *Generated by AI via the team workflow.*

## Agent Brief

**Category:** bug / enhancement
**Parent:** #<epic> (omit if standalone)
**Summary:** one line

**Current behavior:**
**Desired behavior:** (edge cases and error conditions included)

**Decisions (settled in grilling — do not revisit):**
- <decision> — <why, in a clause>

**Key interfaces:** types, signatures, config shapes, API contracts

**Test seams:** where behavior is verified, and prior art in the repo

**Acceptance criteria:**
- [ ] ...

**Assumptions (reversible defaults chosen without the business):**
- <assumption> — tracked in #<business issue>; how to change it later

**Security notes:** threat-model mitigations that are requirements here

**Out of scope:**
- ...

**If you get stuck:** apply `needs-info`, comment the exact question, skip
this ticket, continue with unblocked work. Never guess on anything not covered
above.
```

## A brief is not ready if

- an acceptance criterion cannot be turned into a failing test,
- it says "as appropriate", "etc.", "similar to" without naming the target,
- it depends on access, credentials or a service the cloud runner lacks
  (that is `ready-for-human`, or a separate human-setup ticket),
- a decision it needs is still open and is not listed as an assumption.
